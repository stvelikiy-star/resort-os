# MARINA SMART — эксплуатационная база встроенного помощника

Источник: пользовательская методичка MARINA SMART от 28.09.2026. Этот файл описывает пользовательские сценарии. Правила конкретного объекта не становятся универсальными для других отелей.

## Назначение и главный принцип
MARINA SMART — Hotel OS для управления номерным фондом, бронированиями, гостями, оплатами, уборкой, ремонтом, персоналом, питанием, агентами, QR-сервисами и аналитикой.
Система должна быть основной рабочей системой отеля. В ней фиксируются свободные/занятые номера, бронирования, заезды, выезды, оплаты, состояние номера, уборка, ремонт, обращения гостей, работа персонала, питание, агенты/туроператоры, история гостя и отчётность.
Если действие не зафиксировано в MARINA SMART, для системы оно считается невыполненным.
Заявка из WhatsApp сама по себе не бронь. Получение денег не зарегистрировано как оплата, пока факт оплаты не внесён. Номер не считается готовым только со слов горничной — задача должна быть завершена в системе.

## Вход в систему
Основное управление: https://admin-production-80a1.up.railway.app
Интерфейс персонала «Моя смена»: https://staff-production-69f6.up.railway.app
После открытия появляется «Вход в управление»: логин → пароль → «Войти». Система определяет роль и показывает разрешённые разделы.
Никогда не выдавай пользователю пароли, PIN или другие секреты.

## Роли
OWNER — максимальный доступ: главная панель, шахматка, бронирования, цены, CRM, финансы, отчёты, персонал, агенты, гости, уборка, ремонт, услуги, QR, настройки.
MANAGER — практически полный операционный доступ: бронирования, шахматка, ресепшен, цены, CRM, оплаты, персонал, сервисы, уборка/ремонт, отчётность.
RECEPTION — брони, прибытия, выезды, гости, номера, оплаты, сервисные запросы, QR/PIN гостя, контроль готовности номера.
AGENT — ограниченный доступ: разрешённая шахматка/свободные номера и создание брони по открытому тарифу. Нет внутренних финансов, управления персоналом и административных функций.
MAID — преимущественно «Моя смена»: свои задачи, свободные задачи уборки, номер, приоритет, статус, чек-лист.
TECHNICIAN — ремонтные задачи: номер, описание неисправности, статус, приоритет, свои и свободные заявки.
DINING_STAFF — заказы, питание, гости с питанием, ресторан, статусы заказов.
WAITER — рабочий интерфейс зала/заказов в рамках разрешённых функций.

## Главное меню
Основные разделы: Главная; Супершахматка; Ресепшен / Брони; CRM / Заявки; Финансы; Сервис гостя; Уборка / Ремонт; Отчёты / Аналитика; Настройки.
Дополнительные разделы в «Ещё»: Цены / Сезоны; Групповая бронь; Агенты; Маркетинг; Питание / Ресторан; Настройки услуг; Гости / История; Офферы гостю; QR номеров; QR зон; Рост / Отзывы; Сайт / Контент; Персонал; Сообщения.
Второстепенные функции вынесены в «Ещё», чтобы интерфейс не был перегружен.

## Главная
«Главная» — рабочая панель руководителя для быстрого контроля ситуации. Проверять загрузку, приезжающих, выезжающих, активные брони, задолженность, оплаты, неготовые номера, уборку, ремонт, активные задачи и важные показатели.
Главная не заменяет Супершахматку.

## Супершахматка
Одна строка = один физический номер. Один столбец = одна дата. Одна клетка = одна ночь.
Если заезд 10 июня, выезд 13 июня, заняты ночи 10→11, 11→12, 12→13; 13 июня — дата выезда.
Основные состояния номера:
CLEAN / Готов — чистый, можно заселять.
DIRTY / Уборка — нужна уборка; обычно после CHECK-OUT.
IN_INSPECTION / Проверка — уборка закончена, номер ждёт проверки.
TECH_BLOCK / Ремонт — номер закрыт для продажи; бронировать и заселять нельзя.

## Создание брони из Супершахматки
Открыть Супершахматку → найти номер → выбрать первую свободную дату → выделить необходимые ночи.
Открывается «Новая бронь · выбранные клетки». Проверить номер, категорию, заезд, выезд, количество ночей.
Заполнить имя, телефон, взрослые, дети, email при наличии, комментарий.
Система должна проверить конфликт, TECH_BLOCK, вместимость, тариф, стоимость и доступность.
После успешной проверки подтверждается бронь.
Если номер заняли параллельно, бронь не должна создаться: обновить шахматку и выбрать другой номер.

## Цена брони
Стоимость рассчитывается по тарифам системы: базовая стоимость, ночи, стоимость каждой ночи, дополнительные услуги при наличии, скидка, итог.
Если тариф отсутствует/закрыт или требует подтверждения, обычный сотрудник не должен придумывать цену; вопрос передаётся менеджеру.

## Предоплата
Бронь и полученная оплата — разные события. Фактическая оплата фиксируется отдельно.
В методичке правило «предоплата за первые сутки проживания» относится к текущей настройке AK BERMET и не является универсальным правилом MARINA SMART для всех объектов.

## CRM / Заявки
В CRM / Заявки поступают заявки потенциальных гостей: сайт, обращения, запросы номера/дат и подключённые каналы.
В карточке проверить имя, телефон, даты, взрослых, детей, категорию, источник, предварительную стоимость и требуемую предоплату.
Заявка означает интерес. Бронь означает, что номер реально заблокирован в PMS. Нельзя говорить «номер забронирован», если существует только заявка.

## Ресепшен / Брони
Основной рабочий экран администратора: активные брони, заезды сегодня, выезды сегодня, гарантированные брони, проживающие, завершённые проживания.
Статусы: GUARANTEED — гарантирована; CHECKED_IN — проживает; CHECKED_OUT — выехал; CANCELLED — отменена; NO_SHOW — не заехал.

## Подготовка к заезду
Перед заселением проверить: бронь существует; номер назначен; не TECH_BLOCK; номер «Готов» / CLEAN; даты и количество гостей правильные; оплата/предоплата отражена; нет критической задолженности/ошибки.
Если DIRTY — заселять нельзя. Если IN_INSPECTION — дождаться подтверждения готовности.

## CHECK-IN
Ресепшен / Брони → найти гостя → открыть карточку → проверить → выполнить действие заезда → подтвердить.
После CHECK-IN бронь получает состояние проживания, создаётся/активируется проживание, становится доступен гостевой контур QR/PIN.

## QR/PIN и Guest OS
QR привязан к физическому номеру, а не к конкретному гостю. Постоянный QR может находиться в комнате.
После сканирования система проверяет номер, активное проживание и текущего гостя. Для первого входа используется PIN.
Гость: сканирует QR → открывает MARINA SMART Guest → вводит PIN → получает доступ к своему проживанию.
После CHECK-OUT доступ должен прекращаться.
QR номера не должен напрямую содержать ФИО, телефон, ID гостя или ID брони.
QR номеров: Ещё → QR номеров. Там можно посмотреть, выпустить, перевыпустить и заменить скомпрометированный QR.

## Сервис гостя
Сервис гостя принимает обращения проживающих: уборка, полотенца, бельё, неисправность, трансфер, питание, сауна, экскурсия, обращение к ресепшену.
Типовой цикл: OPEN → IN_PROGRESS → DONE.
Уборка/полотенца/бельё направляются в очередь горничных. Ремонт — технику. Трансфер/питание/экскурсия/ресепшен — соответствующей службе/менеджеру.
Запрос не должен теряться в WhatsApp или устной передаче; он должен стать задачей системы.

## Уборка / Ремонт
Раздел показывает задачи персонала. Типы: уборка, ремонт, запрос гостя.
Статусы по методичке: Открыта → В работе → Проверка → Готово; также возможна Отменена.

## Работа горничной
MARINA SMART — Моя смена. Вверху: «Мои сейчас», «Можно взять», «Завершено».
Свободная задача: «Можно взять» → выбрать номер → «Взять в работу».
После выполнения: «Сдать уборку» → заполнить чек-лист → отметить все пункты → добавить комментарий/подтверждение при необходимости → «Отправить на проверку».
Номер переходит IN_INSPECTION. После проверки — CLEAN / Готов.

## Работа техника
Моя смена → свободные задачи → выбрать ремонт → «Взять в работу» → выполнить → описать выполненное → приложить подтверждение при необходимости → «Завершить ремонт».
При критической неисправности номер должен быть TECH_BLOCK. Пока TECH_BLOCK не снят по правильному процессу, номер нельзя продавать/заселять.

## CHECK-OUT
Ресепшен / Брони → найти гостя → карточка → проверить счёт, остаток, необходимые платежи → CHECK-OUT.
После выезда статус проживания CHECKED_OUT. Номер автоматически должен перейти DIRTY / Нужна уборка, далее формируется задача горничной.
Нормальный цикл номера: гость проживает → CHECK-OUT → DIRTY → задача горничной → IN_PROGRESS → IN_INSPECTION → CLEAN → номер снова готов.

## Финансы и платежи
Финансы контролируют стоимость проживания, полученные оплаты, задолженность, Folio и финансовые факты бронирования.
Заказ/услуга/заявка не являются автоматически фактом оплаты.
Чтобы внести оплату: открыть карточку проживания → проверить гостя, номер брони, сумму, остаток → действие записи платежа → сумма, способ оплаты, номер операции/комментарий при наличии → подтвердить → проверить новый остаток.
Нельзя дублировать платёж. При сомнении сначала найти существующую операцию.

## Цены / Сезоны
Ещё → Цены / Сезоны. Собственник/менеджер управляет тарифами.
Перед сохранением проверить категорию, период, цену, статус продажи.
Если цена отсутствует, система может закрыть продажу категории; это безопаснее, чем выдумывать цену.

## Групповая бронь
Для групп, туров, организаций и больших заездов.
Проверять количество номеров, категории, даты, общую вместимость, тариф, источник, плательщика.
Не создавать десятки отдельных броней без необходимости, если процесс можно оформить группой.

## Агенты
Ещё → Агенты. Для туроператоров, агентств, корпоративных партнёров.
Карточка может содержать название, контакт, статус, историю, связанные бронирования, полученные оплаты, показатели сотрудничества.
Если агент отключён/неактивен, создавать от его имени брони нельзя.

## Питание / Ресторан
Ещё → Питание / Ресторан. Для питания проживающих, ресторанных заказов, столов, бронирований столов, кухни и официантов.
Заказ кухни не означает автоматическое создание гостиничного платежа.

## Работа официанта
Официант может видеть столы и брони столов, посадить гостя, принять заказ, менять статус обслуживания, завершать обслуживание, отмечать no-show брони стола.
Статусы заказа могут включать: Новый → Принят → Готовится → Готов к выдаче → Выдан; также Отменён.

## Гости / История
Ещё → Гости / История. Накопительная карточка гостя: прошлые брони, проживания, номера, обращения, предпочтения, сервисы, история взаимодействий.
Новая бронь не должна уничтожать старую историю.

## Персонал
Ещё → Персонал. OWNER/MANAGER управляют сотрудниками.
При создании: имя, логин, роль, пароль, активность учётной записи. Роль определяет доступ.
Не выдавать всем OWNER/MANAGER. Каждый сотрудник — минимально необходимый доступ.

## Настройки
Настройки — административный раздел: название объекта, логотип, активные модули, настройки системы, параметры отеля.
Менять только ответственным сотрудникам.

## Отчёты / Аналитика
Для собственника/руководителя: загрузка, продажи, бронирования, деньги, задолженность, категории, каналы, агенты, уборка, ремонт, динамика.
Управленческая аналитика MARINA SMART не заменяет официальную бухгалтерскую отчётность.

## Сайт / Контент
Ещё → Сайт / Контент: тексты, блоки, контакты, некоторые медиа.
Контент сайта не должен напрямую менять фактические брони или оплаты.

## Утро администратора
Войти → Главная → заезды сегодня → выезды сегодня → Ресепшен / Брони → номера прибывающих → CLEAN → задолженности → новые CRM-заявки → активные уборки → ремонт → обращения гостей.

## Перед каждым заездом
Проверить: бронь; даты; гостя; назначенный номер; CLEAN; не TECH_BLOCK; предоплату/оплату; критические ошибки; особые пожелания. Только затем CHECK-IN.

## Перед каждым выездом
Проверить гостя, номер, начисления, оплаты, остаток, дополнительные услуги, открытые вопросы. Затем CHECK-OUT.

## Конец смены
Проверить: сегодняшние заезды обработаны; выезды обработаны; no-show корректны; оплаты внесены; нет потерянных заявок; грязные номера отправлены на уборку; критические ремонты зарегистрированы; обращения не зависли; спорные ситуации переданы следующей смене.

## Запрещённые действия
Не создавать две брони «на всякий случай».
Не переносить бронь созданием второй брони.
Не заселять в DIRTY или TECH_BLOCK.
Не считать заявку полноценной бронью.
Не считать обещание оплаты фактическим платежом.
Не удалять данные, чтобы скрыть ошибку.
Не использовать чужую учётную запись.
Не выдавать права выше необходимых.
Не менять системные настройки без понимания последствий.

## Типовые ошибки
«Номер уже занят» → обновить шахматку, выбрать другой номер.
«TECH_BLOCK» → номер закрыт ремонтом, не продавать.
«Тариф требует подтверждения» → менеджеру.
«Превышена вместимость» → другой номер или согласованное дополнительное место.
«Неверный логин или пароль» → проверить учётную запись/официальное восстановление; не выдавать пароль.
«Нет доступа» → действие, вероятно, запрещено ролью; не обходить ограничение.

## Идеальный цикл
Заявка клиента → CRM / Заявки → проверка доступности → бронь → Супершахматка → предоплата по правилу объекта → GUARANTEED → подготовка → CLEAN → CHECK-IN → проживание → QR/PIN → сервисы/питание/обращения → оплаты → CHECK-OUT → DIRTY → уборка → проверка → CLEAN → номер снова доступен.

## Обучение нового администратора
Урок 1: вход и Главное меню.
Урок 2: Супершахматка, свободный/занятый номер.
Урок 3: тестовая бронь.
Урок 4: тестовые CHECK-IN и CHECK-OUT.
Урок 5: CHECK-OUT → DIRTY → уборка → проверка → CLEAN.
Только потом финансы, агенты, тарифы, QR, ресторан, аналитика, персонал.
Три главных раздела для нового ресепшена: Супершахматка; Ресепшен / Брони; Сервис гостя.

## Короткая шпаргалка
Новая заявка → CRM / Заявки.
Найти номер → Супершахматка.
Создать бронь → выделить свободные клетки.
Гость приехал → Ресепшен / Брони → CHECK-IN.
Полотенце → Сервис гостя.
Номер сломан → Уборка / Ремонт → TECH_BLOCK при необходимости.
Гость заплатил → зафиксировать факт оплаты.
Гость выезжает → CHECK-OUT.
После выезда → DIRTY → уборка.
Горничная закончила → IN_INSPECTION.
Номер проверен → CLEAN.
Результаты работы → Отчёты / Аналитика.
