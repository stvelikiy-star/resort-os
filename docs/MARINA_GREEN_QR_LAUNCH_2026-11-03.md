# MARINA SMART: запуск GREEN-API по QR

## Что уже есть и что изменено

Владелец открывает WhatsApp / AI в MARINA SMART. Номер и QR запрашивает backend, привязанный к одному объекту. Токен остаётся на сервере. Новая версия различает QR, ожидание (`timeout`), подтверждение на телефоне (`passkeyRequired`) и уже подключённый номер (`alreadyLogged`).

После запроса QR панель получает актуальное изображение/статус каждые 3 секунды без перекрывающихся запросов. Интервал согласован с текущим локальным лимитом 30 запросов в минуту; это менее частый опрос, чем рекомендованная провайдером 1 секунда. Ожидание ограничено 90 секундами. Устаревшее изображение скрывается через 20 секунд. Можно остановить подключение; скрытая вкладка прекращает обновление. При истечении ожидания, ошибке/лимите или запросе подтверждения на телефоне требуется явное повторное действие.

Публичный объект MARINA_DEMO не может подключать реальный WhatsApp даже при ошибочно заданных ключах. Для тестирования используйте приватный hotel01.

## Что требуется для первого номера

Из уже созданного инстанса GREEN-API нужны три значения:
- `apiUrl` → `GREEN_API_URL`;
- `idInstance` → `GREEN_API_ID_INSTANCE`;
- `apiTokenInstance` → `GREEN_API_TOKEN_INSTANCE`.

Сохраняются только в закрытом файле/секретах приватного объекта, права 600. Ключ OpenAI и токен инстанса GREEN-API — разные секреты. Ключ партнёра для авторизации уже созданного инстанса не нужен.

`compose.marina-green-connection.yaml` добавляет переменные только API приватной fleet-конфигурации. Пример применения ПОСЛЕ доставки проверенной версии на Ubuntu и сохранения параметров в `/home/agent/.config/marina/hotel01-green.env`:

```bash
cd /home/agent/marina-smart-demo
docker compose --env-file .marina-fleet/hotel01.env \
  --env-file /home/agent/.config/marina/hotel01-green.env \
  -f compose.marina-fleet.yaml -f compose.marina-green-connection.yaml \
  up -d --build --no-deps api admin
```

Команда показана для оператора; в рамках этой доработки на Ubuntu не выполнялась. Не запускать из публичного demo-worktree. Существующие данные, PostgreSQL и seed не пересоздаются этой командой, но перед обновлением версии всё равно нужен проверенный резервный снимок и предыдущие образы для отката. При последующих пересозданиях API сохраняйте этот overlay и оба env-файла.

## Приёмка реального подключения

1. Войти собственником в приватный объект, открыть WhatsApp / AI.
2. Проверить состояние, запросить QR, отсканировать из WhatsApp Business → Связанные устройства.
3. Дождаться состояния «Номер авторизован». Проверить истечение QR, повторное открытие и остановку ожидания.
4. Отдельно подтвердить входящее сообщение → переписка правильного отеля → ответ уполномоченного сотрудника → фактическая доставка.
5. Затем подключать базу знаний конкретного отеля, правила ИИ, передачу человеку и ограниченные автоответы.

Авторизация номера не подтверждает работу webhook/приёма, доставки, CRM-автоматизации или ИИ. В этой доработке не включается отправка сообщений и не создаются брони.

## Партнёрская схема

GREEN-API документирует создание инстансов по Partner API и показ QR внутри собственного продукта. Партнёрский токен выдаётся отдельно поддержкой; возможность сотрудничества не подтверждает наличие токена в нашей среде. Создание инстанса может включать посуточное списание. Автоматическое создание платных инстансов сейчас не запускается. Для масштабирования: отдельный инстанс и изолированные секреты на отель, журнал привязок и явное согласие на создание/тарификацию.

Источники, проверены 03.11.2026:
- https://green-api.com/docs/partners/
- https://green-api.com/docs/api/account/QR/

## Дальнейший порядок полного запуска MARINA

1. Реальное QR-подключение приватного объекта.
2. Входящие/исходящие сообщения, дубли, отключение и восстановление, передача человеку.
3. ИИ по знаниям и правилам этого отеля; заявки через контролируемый процесс, подтверждение брони сотрудником.
4. Приёмка ролей и ключевых PMS-сценариев на текущем Ubuntu-релизе.
5. Постоянные HTTPS-адреса, backup/restore и журнал ошибок.
6. Отдельное подключение каждого реального отеля и подтверждённых OTA/платежей. ASKA/BANZAI данные не смешиваются с демо или другими объектами.
