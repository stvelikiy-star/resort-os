## Изменение

- POST `/api/v1/kitchen/stock/receipts` требует `movement_id` UUID.
- Один ID с совпадающими гостиницей, продуктом, количеством, примечанием и автором возвращает прежнее движение с `already_processed=true`.
- Изменённые данные, другая гостиница/автор или коллизия с закупочным приходом дают 409. Разные текстовые представления одного Decimal (`10`, `10.000000`) считаются одинаковым количеством.
- Advisory lock по ID сериализует конкурентные запросы до блокировки позиции. Уникальный ключ дополнительно защищён `ON CONFLICT DO NOTHING`; коллизия не должна становиться 500.
- Повтор возвращает первоначальный `unit_cost_kgs`, не текущую цену справочника. Сам способ определения стоимости нового прихода пока не заменён моделью накладных: это следующий этап.
- OWNER/MANAGER/STORE_STAFF разрешены явно; индивидуальный DINING не повышает COOK до права прямого прихода.
- Платёж, расход OWNER и закупочный документ автоматически не создаются.

## Клиенты

Mobile STORE и оба Staff Web экрана (`StoreStaffStock`, `KitchenStock`) используют тот же контракт. Web-форма вынесена в общий DirectStockReceipt; создание продукта и списание по производству сохранены.

Перед новым действием клиент получает свежий ID из GET склада, сохраняет полный запрос в журнале своей гостиницы/пользователя, затем отправляет POST. При ошибке журнал не удаляется; новая операция заблокирована. После перезапуска предлагается явный повтор того же ID и данных. Подтверждение проверяется по ID, позиции, количеству и флагу отсутствия платежа. Примечания журнала — только фиксированный текст интерфейса, без токенов или гостевых данных.

Mobile использует durable storage (SecureStore на устройстве), без memory fallback для решений о записи. Web — localStorage и Web Locks для согласования вкладок; отсутствие доступа к устойчивому хранилищу/блокировкам запрещает отправку. Web Locks требуют поддерживающий браузер и безопасный контекст (HTTPS; localhost разрешён для CI).

API и клиенты выпускаются согласованно. Старый запрос без `movement_id` получает 422 без записи; новый Mobile при отсутствии серверного receipt ID сохраняет чтение склада, но блокирует небезопасный приход. Все найденные клиентские места прямого прихода и тестовые setup-вызовы обновлены.
