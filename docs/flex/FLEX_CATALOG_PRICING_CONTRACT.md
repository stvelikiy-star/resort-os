# MARINA FLEX — коммерческие SKU, цены и калькуляция (preview)

Статус: **только каталог на чтение и чистый калькулятор без side-effects**. Production, PMS, счета, QR и блокировки не тронуты.

## Каталог

`flex_skus.sku` — стабильный коммерческий артикул, не CSS-кнопка. Допустимы только `AVAILABLE` к продаже; `BETA`, `PLANNED` и `RETIRED` не продаются. В `GET /v1/catalog` доступны только активные **публичные** прайс-версии в KGS; индивидуальные договоры, скидки, настройки отелей и оплата пока не раскрываются и не меняются.

`flex_price_versions` — добавляемые, неизменяемые исторические версии. Для одного SKU новые версии обязаны иметь строго возрастающий номер и `valid_from`; в любой момент **каноническая версия** — последняя по `valid_from` из уже вступивших в силу и не истекших явно по `valid_to`. У предыдущей цены `valid_to=NULL` означает «до последующего изменения»; избыточных обновлений задним числом не делаем.

Для изменения цены в будущем вставляем **новую версию**, не переписывая старую. Исторические invoice lines всё равно должны хранить снимок суммы и версии на момент выставления.

## Калькулятор

`quote_month()` в `services/api/app/flex_pricing.py`:
- принимает только **подтверждённый UUID гостиницы** и цены/сроки/скидки, извлечённые сервером из коммерческого договора;
- `price_version`, `sku`, `product_status`, `pricing_source`, количество, скидка;
- KGS с `Decimal` (0.01 сом, HALF_UP), без float и валютной конвертации;
- ежедневное пропорциональное начисление в календарном месяце, активация включительно;
- скидки в basis points (`10000`=100%), запрещение дублирования одного SKU;
- предсказуемый fingerprint запроса, исходные позиции и полный месяц без ограничений периода;
- `tax_status=NOT_CALCULATED`: **результат не является налоговым или платёжным документом**.

Важно: `renewal_monthly` — стоимость полного месяца для выбранных строк, **не обещание следующего счёта** при будущих активациях/сезонах. Для последующего периода нужно повторно рассчитать quote по действующим на тот период условиям.

Формулы предварительные: пропорция по календарным дням ещё должна быть подтверждена коммерческими договорами, налоговый режим/возвраты/частичные платежи — отдельно. Ни один результат quote не должен автоматически создавать invoice или включать entitlements до соответствующего проверенного backend.

## Параметры для утверждения перед продажами

1. Чёткий состав базовой подписки (целевое значение 10 000 KGS; прежние договоры не заменять).
2. Порядок округления пропорций, валюты, налогов и скидок.
3. Индивидуальные цены по гостиницам, версия договора, полный срок, пауза/сезон.
4. Привязка SKU к точной серверной бизнес-операции (не путать с гостиничным RBAC).
5. Границы доступности внешних интеграций (Booking.com, WhatsApp, ИИ) до их готовности.

## CI

- `scripts/marina_flex_pricing_contract_test.py` — расчёт, регулярный месячный эквивалент, скидки, високосный месяц, границы, история и отказ от неготовых SKU.
- `0003_flex_price_version_guard_preview.sql` — только одноразовая FLEX QA БД, строго возрастающие публикации цен, иммутабельность.
- `scripts/marina_flex_price_version_sql_test.sql` — запрет неверной последовательности, изменения исторической цены, поддержка новой версии после open-ended старой.
- `scripts/marina_flex_control_plane_http_test.py` — опубликованные цены без запланированных функций, ограничения по ролям.
