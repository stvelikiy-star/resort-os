# MARINA FLEX — сверка моей архитектуры с реализацией Codex

Дата: 22.11.2026. Источник реализации: ветка `feat/marina-flex-integration-qa-20261122` @ 424b4e77 (12 модулей `flex_*.py`, 10 preview-SQL, 13 документов). Это **QA-код, не работающая платформа** (по собственному аудиту Codex: NO-GO для коммерческой эксплуатации). Свежие CI-запуски мной не проверялись.
Правило: где Codex ближе к безопасности и фактам — принимается его решение, мои документы считаются заменёнными в указанных местах.

## 1. Принятые решения Codex (мои документы в этих местах заменены)
| Тема | Мой документ | Codex | Итог |
|---|---|---|---|
| Где живёт FLEX | таблицы `flex_*` в базе отеля, RLS | **Отдельная control-plane БД и отдельный API**, отели не имеют прямого доступа | Принято Codex. Мои `flex_*` DDL использовать как справочник полей, не как миграцию в базу отеля |
| Статусы подписки | `GRACE_PERIOD`, `REACTIVATED` как состояние | `TRIAL, ACTIVE, PAYMENT_DUE, GRACE, SUSPENDED, CANCELLED, GRANDFATHERED`; восстановление — событие `REACTIVATE_PAID` | Принято Codex (`GRACE`, `REACTIVATED` = событие журнала). На макетах подписи «Восстановлена» означают событие |
| Роли платформы | SUPER_ADMIN, BILLING, SALES_MANAGER, AUDITOR, INVESTOR_MANAGER + агент/инвестор | `SUPER_ADMIN, BILLING, HOTEL_OWNER, SALES_AGENT, INVESTOR` в `flex_platform_memberships`; SUPER_ADMIN не SQL-роль | Принято Codex. | Идентичность | собственные таблицы пользователей | подписанные EdDSA JWT внешнего issuer + членство в БД; MFA для инвестора и SUPER_ADMIN | Принято Codex; issuer пока QA-симулятор |

| Выплаты агентам/инвесторам | описаны | **отложены**, не строить (QA-only начисления) | Принято: выплат в первой версии нет |

## 2. Покрытие макетов реальным API Codex
Фактические маршруты: `GET /v1/me`, `/v1/hotels`, `/v1/hotels/{id}/subscription`, `/v1/hotels/{id}/invoices`, `/v1/catalog`, `/v1/partner/me/earnings?period=day|week|month`, `/v1/platform/partner-earnings-summary`, `POST /v1/onboarding/hotels`, `.../challenge`, `.../confirm`, `/health`.
| Макет | Что есть | Чего нет (нужен контракт) |
|---|---|---|
| Super Admin — обзор | каталог, отели, сводка обязательств | MRR/ARR/ARPU, три регистра выручки, дебиторка по возрасту, события дня, график |
| Super Admin — карточка отеля | подписка, счета, каталог | позиции с лимитами и «кто подключил», платежи и карантин, журнал, ручные действия (продление/разблокировка), QR |
| Владелец — «Подписка и счета» | подписка, счета | карточки функций и запрос подключения, PDF счёта, QR/платёжная ссылка, статус для баннера |
| Кабинет агента | `/v1/partner/me/earnings` (день/нед/мес) | список «мои отели» со статусом, баланс комиссий по состояниям, KPI/рейтинг |
| Кабинет инвестора | `/v1/partner/me/earnings` | год и «весь период», три состояния денег, остаток возврата вклада, договор, документы, уведомления, прогноз |
| Инвестор (телефон) | то же | то же |
Вывод: макеты — цель; реальный backend покрывает чтение подписок/счетов/каталога и доходов день–месяц. UI подключать только к тем маршрутам, что есть; остальное — отдельные контракты (§4).

## 3. Правки к моим макетам по результатам сверки
1. Сайдбар ролей: убрать пункты, которых нет в ролях Codex (в этой версии: только SUPER_ADMIN, BILLING, HOTEL_OWNER, SALES_AGENT, INVESTOR).
2. Инвестор: «Возвращено» считать по **фактически выплаченному**; показывать «Начислено» отдельно и не называть его возвратом. Кнопки выплат не показывать (выплаты отложены).
3. Подпись фаз: «Возврат вклада → Дополнительные выплаты» включается только после записи фактической выплаты.
4. Статус «GRACE» на английском в журнале, «Льготный период» в интерфейсе.
5. Везде метка «QA / демо» пока backend не в бою.

## 4. Контракты, которые нужны от Codex для UI (в порядке пользы)
1. `GET /v1/hotels/{id}/entitlements` (список позиций, лимиты, источник подключения).
2. `GET /v1/platform/metrics?from=&to=&dims=` (три регистра, MRR/ARR/ARPU, дебиторка).
3. `GET /v1/hotels/{id}/payments` и `.../events` (платежи, дубли, карантин).
4. `GET /v1/investor/me/contract` + `/summary` (вклад, фактический возврат, фаза, три состояния денег).
5. `GET /v1/agent/me/hotels` и `/balance`.
6. `GET /v1/hotels/{id}/audit`.
Все — только чтение, с теми же RLS/JWT-проверками. Записывающие действия (ручная разблокировка, запросы подключения) — после отдельного согласования.

## 5. Обновлённый список решений владельца
Закрыто сверкой: база без налогов; возврат вклада по фактическим выплатам; отдельная БД FLEX; предел суммарных долей по аллокации.
Остаётся: цены функций и пакетов; `dueDays/graceDays` и порядок блокировки; провайдер оплаты и договор (Codex упоминает Finik — договор не подписан); налоговая модель счетов; проценты комиссий и условия инвесторов; метод деления на границе фаз; юридическая форма договоров; отдельный релизный контур FLEX и судьба стопки #574–584; нужны ли роли SALES_MANAGER/AUDITOR/INVESTOR_MANAGER.
