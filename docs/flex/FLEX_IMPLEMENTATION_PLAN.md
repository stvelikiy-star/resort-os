Только проект. Ничего не внедрено. Production, `main`, действующие БД, Docker и релиз не менялись.

## P0 — основа (без изменений поведения для клиентов)
| # | Задача | Критерий приёмки |
|---|---|---|
| P0.1 | Включить и принять `MARINA_TENANT_CONTEXT_ENABLED` на тестовой среде (сейчас `false` по умолчанию) | Тест двух отелей: чужой `propertyId` во всех admin/ops/staff маршрутах → отказ |
| P0.2 | Миграция `flex_*` таблиц (пустых) + `UNIQUE(tenantId,id)` на `properties` | Откат `DROP` проверен; существующие таблицы без изменений |

| P0.4 | Серверный `entitlement`-слой в режиме `SHADOW` (лог «был бы отказ») | Журнал за ≥2 недели; ложных отказов 0 |

## P2 — рост
Планировщик автоотключения, аналитика MRR/ARR/ARPU/churn, КП, сезонные подписки, уведомления; затем (отдельно согласовать) платёжные провайдеры, двусторонний Channel Manager, per-hotel ИИ-флаги.

## Риски
1. Мультитенантность выключена по умолчанию, RLS нет → утечки между отелями возможны при ошибке запроса. Закрывается P0.1/P0.5.
2. Серверной проверки `enabledModules` сейчас нет: включение `ENFORCE` без `SHADOW` может отрезать действующих клиентов.
3. Продажа ещё не реализованных интеграций (Booking.com, провайдеры платежей, NFC).
4. Смешение ролей: у `OWNER` отеля не должно быть платформенных прав.
5. Конфликт имён: два отдельных набора ключей (секции прав сотрудников и модули подписки) — вводится таблица соответствия.

## Зависимости
P0.1 → P0.4 → P1.4. P0.2 → P0.3 → P0.4. P1.1 → P1.2 → P1.3.

## Решения, требующие согласования владельца
1. Цены модулей и скидки (в задании только база 10 000 сом).
2. Начисление при подключении в середине периода: пропорционально или с следующего.
3. Срок GRACE (дней) и что делать после: `READ_ONLY` или полная блокировка.
4. Длительность пробного периода и кто может его выдавать.
5. Включать ли per-hotel ограничения для существующих клиентов или оставить grandfathered навсегда.
6. Валюта счетов (KGS) и документ-основание оплаты.
7. Кто в роли `BILLING` может менять цены (отдельно от Super Admin).
8. Статус Channel Manager в каталоге: «в разработке» без продаж до реальной интеграции.
