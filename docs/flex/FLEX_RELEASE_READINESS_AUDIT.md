## B. CI и выпуск

- PR #574–584 остаются Draft. Специализированные FLEX CI прошли, но **это не является общим разрешением объединить их в main**.
- Базовый #574 имеет отказ \`release-rc-truth\`. Файл \`scripts/verify_marina_november_release_boundary.py\` намеренно фиксирует ноябрьскую PMS и узкий перечень P0 blob digest. Править guard только ради зелёной галочки запрещено.
- Приёмка нового MARINA FLEX должна получить **собственный явно утверждённый релизный контур** и согласованный процесс расширения scope, не ослабляя исторический 0.62.2/November no-cutover.
- Новая интеграционная CI проверяет десять preview миграций по порядку, PostgreSQL backup/restore в отдельную БД, RLS/индексы/исторические триггеры, регрессии ledger и недопустимость изменения исходной гостиничной PMS.
- Backup/restore здесь сделан **только в GitHub Actions на одноразовой PostgreSQL**, без внешнего зашифрованного R2 и без реальных коммерческих данных. Нельзя выдавать это за подтверждённую производственную стратегию DR.

## C. Критические пробелы P0

1. **Согласование коммерческих условий.** Материалы тарифов и инвесторов являются предложениями. Для продаваемого SKU нужны договор, версия цены, налогообложение, возврат и право на период. Старые отельные договоры grandfathered.
2. **Production-grade отдельная FLEX БД.** Версионированные миграции, health/rollback, offsite encrypted backups, test restore, secret management, запрет прямого подключения отелей к БД.
3. **Доверенная идентичность.** Реальный issuer, MFA, revocation, серверные права и безопасная регистрация доверенного PMS instance; signed challenge без настоящего PMS signer пока QA.
4. **Платёжный провайдер.** Подписанный merchant договор и официальные тестовые ключи; верификация подлинной подписи, callback и банковская сверка. QA Ed25519 не является Finik RSA.
5. **Безопасный billing writer.** Только после банковской сверки, KGS fiscal rules, транзакционного отнесения платежа к отелю и invoice, webhook replay и возврата.
6. **Подключение entitlements к гостиничной PMS.** \`OFF\` по умолчанию, потом \`SHADOW\`, тесты каждой функциональной роли и безопасное \`ENFORCE\`; нельзя отказывать в завершении активного проживания, возвратах и экспорте.
7. **Рабочие UI и полные HTTP E2E.** Claude Code делает дизайн; backend передаёт стабильные API контракты. До приёмки не считать дашборды и персональные кабинеты готовыми.
8. **Утверждённая защита релиза.** Отдельный релизный кандидат с собственным обязательным CI; исторический Release RC Truth не удалять и не переписывать.
9. **Итоговая приёмка основной MARINA SMART.** Отдельно повторить мобильные нативные роли, PMS, ресторан/кухню/склад, OWNER-finance, RU/KG/EN и реальный HTTPS/бэкапы на актуальном рабочем SHA; FLEX QA не заменяет этот выпуск.
