# MARINA SMART FLEX 2.0 — единый технический отчёт

Дата: 22.11.2026. Репозиторий `stvelikiy-star/resort-os`, база `main` @ 2642eed. Ветка `docs/marina-flex2-commercial-20261122` (поверх `docs/marina-flex-architecture-20261122`). Только документация.

## 1. Что уже существует и можно использовать
`tenants` + `properties.tenantId` (под флагом, выключен); `section_permissions` (права по путям); `AuditLog`; шаблон HMAC-проверки вебхуков; `runtime_capabilities` (fail-closed флаги платежей); `payment_idempotency` (образец); стиль Future Luxury; ручной ввод броней каналов; ~267 маршрутов API, 126 модулей.
## 2. Что предстоит разработать
Каталог SKU/функций/лимитов; подписки; биллинг и пересчёт; QR/провайдеры; реестр платежей; автомат блокировки; агенты и комиссии; аналитика; Super Admin; RLS; entitlement-проверка по маршрутам (сегодня `enabledModules` только в интерфейсе).
## 3. Что в FLEX 1 нужно изменить
См. COMMERCIAL §0: модуль→функция/SKU; `subscription_modules`→`subscription_items`; статусы → единый автомат; ручные платежи → три слоя; кредит-ноты; роли платформы + агенты; три регистра выручки; лестница блокировки.
## 4. Интеграция без потери функционала
Только добавление таблиц `flex_*`; grandfathered-подписки; SHADOW → ENFORCE по одному отелю; ядро неотключаемо; откат флагами и DROP новых таблиц.
## 5. Решения владельца
1. Цены функций, пакетов, скидки, акции. 2. Метод пропорции при подключении в середине периода. 3. `dueDays`/`graceDays`, порядок блокировки, блокировать ли новые брони в SUSPENDED. 4. Провайдер(ы) оплаты и договор (ELQR-банки/агрегатор). 5. Комиссии: проценты, разовые/регулярные, срок регулярных, база (с налогами/без), удержание при возвратах. 6. Грандфазеринг навсегда или миграция тарифов. 7. Кто выдаёт пробные и ручные разблокировки. 8. Сроки хранения данных (юрист). 9. 2FA/IP для платформы. 10. Валюты счетов.
## 6. План P0/P1/P2
См. `FLEX_IMPLEMENTATION_ROADMAP.md`.
## 7. Технические риски
| Риск | Устранение |
|---|---|
| Мультитенантность выключена, нет RLS | P0: включить в тесте, RLS на `flex_*`, тесты изоляции |
| Серверной проверки модулей нет | SHADOW перед ENFORCE |
| Нет подтверждённого платёжного провайдера | Адаптер; ручной режим до договора; не заявлять интеграцию |
| Двойное зачисление платежа/комиссии | UNIQUE-ключи, идемпотентность, транзакция |
| Блокировка ломает активные операции | Проверка открытых операций, READ_ONLY, неприкосновенные зоны |
| Путаница `BookingAgent` и агентов MARINA | Отдельные таблицы и вход |
| Двойной учёт выручки | Три регистра, единый источник |
| Изменение цен задним числом | Версионирование, цена в позиции |
| Пропуск вебхуков | `fetch_status` сверка |
| Утечка данных агенту | Отдельные API, RLS, тесты |
