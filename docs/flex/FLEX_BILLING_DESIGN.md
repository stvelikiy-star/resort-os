# MARINA SMART FLEX — подписки, начисления и платежи

Только проект. Суммы ниже — параметры каталога, не обязательства; **цены модулей в задании не заданы и придумываться не должны** (решает владелец). Известно одно: базовый тариф 10 000 сом/мес.

## Жизненный цикл подписки
`TRIAL → ACTIVE → GRACE → SUSPENDED → CANCELLED`; отдельно `GRANDFATHERED` для существующих отелей (без ограничений до отдельного решения).
- **TRIAL**: модуль включён на N дней, начислений нет, по окончании автоматически → `OFF` (данные сохраняются).
- **ACTIVE**: период оплачен/согласован (месяц, сезон, произвольный период).
- **GRACE**: срок вышел, счёт не оплачен — N дней доступ сохраняется, показывается предупреждение владельцу.
- **SUSPENDED**: платные модули → `READ_ONLY` (история видна, новые операции запрещены), ядро работает.
- Ручное управление: Super Admin может продлить, включить на период, выдать пробный доступ, поставить скидку; всё пишется в `flex_change_log`.

## Автоматическое отключение
Планировщик раз в сутки: находит `endsAt/graceEndsAt` < now → пересчитывает entitlements → пишет журнал. Модуль с незакрытыми операциями (активные заказы кухни, открытые фолио, брони через канал) переходит в `READ_ONLY`, а не в `OFF`, пока операции не закрыты.

## Начисление
- Строка счёта = модуль × период × цена (с учётом `priceOverride`, `discountPct`, индивидуального КП).
- Счёт формируется 1-го числа или при подключении (пропорционально — **требует решения**, см. вопросы).
- Изменение каталожной цены **не** меняет действующие подписки автоматически: цена фиксируется в подписке в момент подключения.

## Платежи
Этап 1: только ручная отметка (`flex_payments`, метод, дата, подтверждающий документ, кто отметил). Автосписание и провайдеры — отдельный этап и отдельное подтверждение: в коде провайдеры отключены (`payment_operations=false`, `mkassa=false`).

## Аналитика Super Admin
MRR = сумма месячных начислений активных подписок; ARR = MRR×12; ARPU = MRR / число активных отелей; churn = отключённые за месяц / активные на начало; выручка по модулям — группировка строк счетов. Считать только по выставленным и оплаченным счетам, без прогнозов, не заданных формулой.

## Аудит
Все изменения подписок, цен, скидок, ручных выдач и платежей — в `flex_change_log` (неизменяемая вставка), с актором и значениями до/после.
