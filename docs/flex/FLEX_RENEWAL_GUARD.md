# MARINA SMART FLEX — безопасное продление подписки

Дата: 2026-11-22. Статус: **чистый серверный decision engine, без исполнения**.

## Проверяемые условия продления

Подписка гостиницы может быть предложена к продлению, только если:
- Гостиница и инвойс ссылаются на один и тот же проверенный FLEX hotel UUID.
- Инвойс связан с конкретной версией действующего подписанного договора и подтверждённой MARINA SMART ↔ FLEX связью.
- Оплачиваемый период — **точно следующий календарный месяц** после предыдущего договора, без дублирования/пробелов.
- Сумма, фактически отнесённая на строки счёта с учётом возвратов, равна полной утверждённой стоимости; остаток задолженности равен нулю.
- Существует подтверждённая запись поступления с проверяемым UUID и разумной датой.
- Цепочка доказательства по реальному банку должна исходить из отдельно проверенного и сверенного провайдера. Уведомления, QR, клиентские скриншоты и CI-симулятор — не доказательство поступления настоящих денег.
- Отменённые и grandfathered договоры **не изменяются автоматически**.

В app/flex_renewal.py функция decide_renewal возвращает Proposal ONLY, никогда не выполняет SQL, не вызывает платежи и не меняет PMS или права сотрудника. Для искусственных проверенных CI поступлений возвращает CI_ONLY_NEVER_RENEW_PRODUCTION: даже успешные тесты sandbox не дают права включить реальные платные функции. Если внешняя банковская сверка когда-либо подтвердит данные, результат останется AWAIT_APPROVED_BANK_RENEWAL_WRITER — для отдельного защищённого workflow.

## Что нужно до включения автопродления
1. Коммерческие условия (точная календарная граница/таймзона, grace period, договорные скидки, налоги и переплаты).
2. Bank provider signed webhook verification и независимая сверка status/merchant statements в реальной sandbox среде. Ни одной такой операции в текущем PR нет.
3. Финансовый write service с idempotency, transaction/CAS на подписку и исходный invoice, auditable журнал продлений, RLS, двухсторонние тесты отелей.
4. Отдельный контролируемый ENFORCE feature entitlement rollout, сохранность операций с активными гостями, возвраты/откаты/экспорт/оплата и защита grandfathered.
5. Строгий Release RC Truth без отключения и одобрение релизной комиссии.

## Реализованная проверка
scripts/marina_flex_renewal_decision_test.py: полный платёж и тестовый платёж, частичная оплата, возврат, чужой отель, другой договор, неправильный месяц, неподтверждённая подпись, отсутствие платежа, legacy/cancelled, неконсистентный баланс. Никакого обновления базы данных или сайта.

**Ограничение:** параметры передаются из уже проверенного внутреннего DB snapshot и trusted provider, никогда из JSON гостиничного пользователя; текущий код только математический guard. Реальный live-автоперевод НЕ реализован.
