# MARINA SMART · Приёмка обновления, 19 ноября 2026

**Контрольная точка после этапов 1–3. Замена старой версии не прошла приёмку.** На двух изолированных PostgreSQL 16.10 сохранились первичные записи, деньги и связи. Изменились даты обновления двух отелей. Прежняя роль питания потеряла доступ к заказам, а клиентский сайт отверг ранее опубликованную страницу. Разбор этих расхождений предшествует этапам 4–7.

## Ответы для владельца

1. **Сотрудник DINING_STAFF не может продолжить прежнюю смену.** Вход сохранён. В обеих версиях браузер показывает «Открыть Kitchen Admin». Список заказов с тем же пользователем возвращал 200, после обновления возвращает 403. В новой версии COOK читает заказы и меню, WAITER получает 200 на ресторанном плане зала. Старые сотрудники сохранили прежнюю роль. Назначить конкретных поваров и официантов должен владелец по обязанностям.
2. **Старая публикация сама не открывается на новом клиентском сайте.** Тот же документ RU остался в базе. В обычном режиме API он читается. В клиентском профиле, включённом в compose.marina-production.yaml:105, и API контента, и главная через Caddy вернули 422. Новая полноценная EN-публикация открылась с брендом ALPHA. Старая ссылка /rooms раньше открывала каталог, новая вернула HTTP 200 с заглушкой. Уровень HTTP сам по себе здесь вводит в заблуждение.
3. **У RECEPTION расширено чтение.** Общая шахматка и список диалогов изменились с 403 на 200. В новом браузере видны «Шахматка» и «WhatsApp / AI». Шахматка передаёт компоненту readOnlyMode. Отдельный Inbox отсутствует среди модулей по умолчанию. Предыдущее утверждение о скрытой шахматке для этого профиля опровергнуто. Владелец должен отдельно решить, нужны ли этой роли чтение шахматки, всех диалогов и раздел WhatsApp. Провайдер не подключался.
