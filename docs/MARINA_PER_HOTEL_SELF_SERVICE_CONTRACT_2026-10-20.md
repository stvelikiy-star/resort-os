# MARINA SMART — неизменяемый контракт независимости отелей

Дата: 2026-10-20. Утверждённое требование владельца AI PROF KG: при обслуживании 10–20 гостиниц каждая гостиница имеет самостоятельную базу данных, номерной фонд, сезонность, тарифы, правила и сотрудников. **Все регулярные настройки выполняет сам отель в интерфейсе MARINA SMART, без SQL, терминала и обращений к разработчику.** Настройки отеля А не влияют на Б.

## Изоляция
- Для текущей архитектуры использовать отдельные PostgreSQL DB/volume + property-pinned API per hotel; отдельный Compose namespace, network, env secrets, user sessions, backup set.
- Никогда не дублировать гостевую базу между объектами, не объединять административные аккаунты отелей и не переключать окружение по непроверенному пользовательскому полю.
- Шаблон scripts/marina_fleet.py — синтетический staging прототип. Не обещать работу 20 активных отелей без реальных метрик Ubuntu и пилотной проверки. Имена «hotel01»/«hotel02» — тестовые и не должны попадать в реальные отели.

## Подтверждено чтением реализации UI/API
1. `Настройки → Настройка отеля`: собственник/менеджер задаёт название, часовой пояс, валюту, время check-in/check-out, загружает логотип, включает модули.
2. `Типы размещения`: добавление/редактирование категорий, вместимости взрослых/детей; удаление с серверными ограничениями.
3. `Номерной фонд`: добавить, редактировать, отключить, удалить номер, корпус/этаж, кровати, массовое создание; изменения используются шахматкой.
4. `Цены / Сезоны`: для каждой категории добавить/изменить период, даты включительно, цену за ночь, продажный статус OPEN/CLOSED/CONFIRM_REQUIRED, питание и комментарии. Перекрытия периодов отклоняются API. Booking preview/commit перепроверяет цены на сервере.
5. `Персонал`: создание и редактирование сотрудника, роль, пароль и блокировка доступа через UI.
6. `Ресепшен / Брони`, `Шахматка`, `Сервис гостя`, `Каналы продаж` — существующие рабочие экраны; не менять привычный дизайн.

## Требования, для которых полное самообслуживание ещё НЕ подтверждено
- **Предоплата**: процент/фиксированная сумма/первые сутки, срок оплаты, порядок подтверждения.
- **Отмена и незаезд**: окна бесплатной отмены, штраф, возврат, no-show.
- **Доплаты**: дети, доп. места, праздничные периоды, сборы, доп. услуги.
- **Каналы продаж**: индивидуальные комиссии, доступность по провайдеру, mapping, официальный автоматический API; пока есть ручные операции/CSV.
- **AI знания отеля**: автоматическое использование актуальных правил и услуг каждого отеля, тесты запрета межотельных данных; не считать наличие read-only помощника подтверждением всех знаний.
- **Сайт отеля / контент / коммуникации**: реальные end-to-end сохранение и публикация по каждому отелю.
- **Работа без программиста**: мастер первичной настройки, права owner/admin, атомарность изменений, понятная проверка и кнопка отката, role-based acceptance тесты.
До отдельного успешного E2E не заявлять эти области как полностью самонастраиваемые.

## Приёмка каждого нового отеля (через UI)
1. Администратор сети регистрирует новый пустой объект (технический provisioning только до появления безопасного self-service control plane).
2. Собственник открывает индивидуальную ссылку, сам задаёт имя, логотип, валюту, время CI/CO.
3. Собственник добавляет две категории и три физических номера; обновляет шахматку и убеждается, что остальные отели неизменны.
4. Создаёт тариф 3000 KGS до конца месяца и 4500 KGS со следующего; бронирует период пересечения и сверяет ночную сумму.
5. Создаёт сотрудника, ограничивает его роль, проверяет отсутствие чужих прав.
6. Настраивает предоплату, отмену, no-show и услуги **только после появления подтверждённого UI и серверной логики**.
7. Создаёт бронь, HOLD, заезд, выезд, задачу уборки, проверяет аудит, резервную копию и восстановление.
8. Открывает независимую сессию второго отеля; убеждается, что ни одна запись, цена, контакт или справка AI первого не видна.

**Ключевое правило:** персонал отеля самостоятельно настраивает свойства своего отеля, но никогда не получает доступ к Docker, инфраструктуре или данным соседей.
